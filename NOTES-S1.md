## 5. Behaviour and schema facts

- Schema: exactly spec 2.3 (`PRAGMA user_version=1`, `SCHEMA_SQL` in `src/store.rs`; all 12 tables with the spec's columns in the same order); S1b needed no schema change. All timestamps are Unix **nanoseconds** (i64). `blobs.id` and `points.tree_id` are 32-byte BLOBs. `changes.old_id/new_id` are hex TEXT, `x:<reason>` for a path not captured, or NULL for absent. **Modes in trees and in `changes.old_mode/new_mode` are the DECIMAL integers 644 or 755** (755 when any exec bit is set, else 644; nothing else is kept). They are NOT octal values. Restore maps them to real `0o644`/`0o755` before any syscall; never pass `entry.mode` to `from_mode` or `write_atomic`, which take real Unix modes. No `changes` rows for directories. The first point has no baseline, so no `changes` rows. `sessions.notified_restore_id` tracks the newest restore each session was told about.
- Point kinds: `start`, `end`, `tool` (the only invisible kind), `pre_bash` (note = masked command preview), `pre_restore` (pinned), `restored` (made by every `back` and `undo`; the newest point is of this kind right after a restore). `partial=1` when the walk hit its entry cap or a folder was unreadable (paths the walk could not see are carried forward from the previous tree, so nothing looks deleted), or any file was left as `x:cap` (hash time budget or the 100 MiB new-bytes cap). `x:too_big`, `x:db_busy`, `x:name`, `x:special` and a single unreadable file do NOT make a point partial; they only appear in `not_captured`. `dropped=1` = thinned (never deleted from the table). A turn has `start_point` NULL when the disk was too full to capture. The edit-family PostToolUse makes no point (the change is recorded on the next point).
- Tree entries (`store::TreeEntry`): kind `f` file, `l` symlink, `s` secret file (encrypted, keyed id: read it with `Ws::read_secret`), `d` directory, `x` not captured (the id field holds the reason code: `cap`, `too_big`, `db_busy`, `unreadable`, `name`, `special`). Canonical JSON `{"v":1,"e":[[name,type,mode,id_hex,size],...]}` (hand-written `encode_tree`, tested against serde_json). A restore skips `x` entries and says so.
- Secrets: XChaCha20-Poly1305, keyed id, key file `torpor-key-v1 <key_id 8hex> <64hex>` created at the first secret capture (`create_new`, 0600 in a 0700 folder). A changed key makes every secret file appear changed once (class `outside`). Which files count as secret: `scan::is_secret` (`.env*` except `.example/.sample/.template`, `*.pem`, `*.key`, `*.p12`, `id_*`, `.npmrc`, `.netrc`, `.pypirc`, `credentials*`, `*.tfstate*`, `*.kdbx`, `service-account*.json`, and files under `.aws`, `.ssh`, `.gnupg`, `.kube`, `.config/gcloud`, `.docker/config.json`).
- Capture and attribution: `meta.consumed_event_id` is a watermark bumped at each full scan (classification reads the OLD value). Classes per spec 4.3: `edit`, `shell`, `shared`, `outside`, `subagent` (via `agent_id`), and `restore` for the gap rows a restore writes. Gap changes are recorded on the `start` point with `turn_id` NULL. An implied end (a new prompt while a turn is open) writes two points. SubagentStop is a `tool_events` row. Slow mode cannot tell main-agent Bash from subagent Bash inside one turn (subagent wins). Mask scanners (`src/mask.rs`) are hand-written with ASCII-only case folding (`regex` is a dev-dependency used as a differential oracle).
- Transactions: every event runs inside one `Transaction::new_unchecked(&ws.conn, Immediate)`; a capture runs inside `SAVEPOINT cap` (on failure `ROLLBACK TO`, `fault_tx`, the event goes on). Orphan loose files left by a rolled-back capture are removed by GC after the grace. The heartbeat is upserted in the same transaction. SQLite: WAL, `synchronous=NORMAL`, `busy_timeout=1000 ms`, `NO_CKPT_ON_CLOSE`; `Ws::drop` truncates the WAL when `-wal` is over 512 KiB (so `-wal` and `-shm` stay on disk between hooks; the tests expect them).
- Locks: hooks take the shared lock; restore, recover, undo, gc and forget take `lock_exclusive`. A busy store prints "Torpor is busy with another restore or cleanup. Try again in a minute." (exit 1). Every hook opens the store with `create=true` (the first hook in a folder makes it; a refused root makes nothing); the CLI opens with `create=false` (missing store: exit 5, "Torpor has no save points for this folder yet.").
- Retention (`src/retention.rs`): `window_days` = Claude Code's `cleanupPeriodDays` (30 if unset, at least 2, with a note) or `torpor retain`. `thin` drops points older than the window W, drops `tool` points after 2 days, keeps only the last visible unpinned point per UTC day after 2 days, and nulls turn previews, command previews and `pre_bash` notes at W. A store over 2 GiB thins harder (1 day in full detail, 7-day window; sets `meta.thinned_harder_at`; status shows the 2 GB note for 14 days). `thin_if_due` runs at SessionStart at most once per 24 h. `gc` has a 1-day grace, marks from every non-dropped point plus the newest, and a tree that cannot be read stops the run.
- Restore notice (`hook::restore_notice`): shows ONLY the newest unseen restore (`restores.status IN ('done','partial')`), once per session; new sessions start as having seen earlier restores (`turn::touch_session`). If a restore is `applying`, UserPromptSubmit emits `MSG_RESTORE_INTERRUPTED`. `torpor log` lists every restore as a gap row.
- Protected paths: PreToolUse denies edit-family writes into TORPOR_HOME or the key file (the kernel-resolved path with symlinks, `..` and dangling links followed, and the text-folded path) and Bash commands that name them (section 8). While Torpor is off these denies stay active. Known limit: a hardlink to the key file used through another name is not covered by the edit-family check.
- `status` (`src/status.rs`): problem sources 1-5: faults (shown once), disk paused, no heartbeat / a live Claude session without hooks / a silent session (flags only sessions whose last hook was Stop or StopFailure and whose transcript is more than 120 s newer than the last heartbeat), lost key file, deep-check list, and **#4 settings files**. `settings_findings(root)` (private) reads the user, project, project-local and managed settings (`CLAUDE_CODE_MANAGED_SETTINGS_PATH` honored, else the OS folder, plus `managed-settings.d/*.json`) and reports `disableAllHooks`, `allowManagedHooksOnly` and `enabledPlugins["torpor@kylne700"]==false` as problems ("... so nothing is being saved.") and `strictPluginOnlyCustomization` as a hedged note only. It reads `<claude_dir>/sessions/*.json` only (never `*.key`; a FIFO named `.key` is in the test). The last lines are "Undo and back reach back N days (set with torpor retain | your Claude Code cleanup setting)." and, when there is a turn, "Undo the last turn: torpor undo K. Go back one step: torpor back 1."
- Scan (`src/scan.rs`): `ignore::WalkBuilder`; hard excludes (`EXCLUDED_DIRS`: `node_modules`, framework build and cache folders, `dist`, `build`, `__pycache__`, `coverage`, `.terraform`, `Pods`, `.torpor-stage`, ...; `.git`; `target` next to a `Cargo.toml`; `venv`/`.venv` with a `pyvenv.cfg`; names ending `-wal`, `-shm`, `-journal`; `.torpor-*.tmp`). Precious (saved even when gitignored): `.env`, `.env.*`, `*.db`, `*.sqlite*`, `*.sql`. Caps: normal files 2 MiB, secret 1 MiB, precious 64 MiB, 100 MiB of new bytes per save point, 200,000 entries.
- `.torporignore`: works like `.gitignore`; for the precious opt-out only the TOP-LEVEL file is read (a nested one cannot drop `.env`/`*.db`/`*.sql` files). `deep_check` may still list files under an ignored folder.
- Texts: a newer store at SessionStart: "Torpor: This project's records were written by a newer Torpor. Update the plugin." (the CLI prints the same without the prefix, exit 3). The refused-root message says "whole home folder" also for `/`. A project root inside the store is refused silently.

## 6. Restore, undo, recover (src/restore.rs, src/merge.rs)

- `back N | --turn K | --id P [--with-data] [--dry-run]`. Bare N is relative: visible states newest first, equal trees collapsed, leading states equal to the live tree dropped, restore state N. `--turn K` = the end point of turn K. `undo K [--dry-run]` takes turn K out of the live folder (line-level 3-way merge with `diffy`, `src/merge.rs`); any conflict means nothing is written and the files are listed. `recover` finishes an interrupted restore. When the files already match the target, `back` exits 0 with "Your files already match {label}. Nothing to do." and makes no `restored` point.
- Protocol (spec 6.2/6.3): exclusive lock; free-space check (`SPARE_BYTES` = 256 MiB must stay); the pinned `pre_restore` point is taken first inside a transaction that stays open while the plan is built (it is rolled back when nothing changes); every saved copy about to be replaced or removed is read back and hash-verified; new content is written into `<project>/.torpor-stage/<id>/`; the journal `<store>/<project id>/journal/restore-<id>.journal` (JSON lines: header, entries, done lines) is written; then each entry is applied (rename into place, delete); a `restored` point is captured; the `restores` row goes `staging` -> `applying` -> `done`/`partial`/`cancelled`. A kill at any step leaves the folder exactly before or after once `recover` has run (A3). Nothing outside the stage folder changes before the journal exists.
- Modes (lead's decision): secret entries are always written 0600 (0700 if the tree says 755); a file that exists keeps its live mode with the exec bit set from the tree; a recreated plain file gets `0o644`/`0o755` (umask applies).
- Databases: not rewound unless `--with-data`; `undo` never rewinds them (`DB_NOTE`). A database that is open (`-wal` non-empty or `-journal` present) makes the whole restore refuse: "Stop your app first: ... Nothing was changed."
- Empty folders are not recreated or removed by undo unless a saved file lived in them. A secret file that changed since is a merge conflict (no text merge).
- Exit codes: 0 done, 1 error (also "busy"), 2 usage, 3 refused for safety, 4 partly done, 5 turn or save point not found.

## 7. CLI (src/cli.rs) and --json schemas

Commands (`cli::HELP`): status [--all] [--json], log [-n N] [--json], show K | --id P [--json], back, undo, recover, init, gc, quiet on|off, statusline [-- <old command>], version, help, and the internal `hook <Event>`. User-only (refuse when `CLAUDECODE` is non-empty): off, on, forget [--all | --before YYYY-MM-DD], retain DAYS.
- `log --json` = array of `{turn, point, at_ms, who, preview, files: [{class, path}]}`. `turn` is the turn number, or null for a gap row (changes made between turns, or a restore), where `point` is the point id and `who` is `-`. `who` for turn rows: `you` (human), `task` (task notification), `timer` (scheduled), `?` (unknown), otherwise the origin string (e.g. `sdk`). Gap rows have a class such as `shared`, `rewind`, `background`, `restore` and text like "put back by Torpor: ...".
- `show K --json` = `{turn: {n, at_ms, who, preview, start_point, end_point} | null, point: {id, text} | null, files: [{path, class, change, added, removed, command}], points: [{id, kind, text}]}`. `change` is one of `new`, `deleted`, `changed`, `mode`, `not saved` (the JSON leaves out the reason for `not saved`); `added`/`removed` are line counts for text files; `command` is the (shortened) shell command for shell files. `show --id P` fills `point` and leaves `turn` null (invisible points are accepted). Example `points` entry: `{id: 3, kind: "pre_bash", text: "before rm -f old.txt && ..."}`.
- `status --json` = `{saving, off, points, oldest_at_ms, last_at_ms, bytes, mode, scan_ms, file_count, retain_days, last_turn: {n, preview, edits, shell, subagent} | null, not_saved: [{path, why}], not_saved_total, problems, notes}`.
- `statusline` reads Claude Code's status JSON on stdin (it looks for `workspace.project_dir`, `workspace.current_dir`, then `cwd`; these field names are assumed, NOT VERIFIED) and prints `torpor · 5 save points · saved just now` (or `· last <ago>`, plus `· see torpor status` when there are problems). Other texts: `torpor · off`, `torpor · hooks not running`, `torpor · not saving this folder`, `torpor · paused: disk full`, `torpor · problem: run torpor status`. With `-- cmd` the user's own status line command runs first (`sh -c`, single argument, 2 s limit) and Torpor's segment is appended.
- `forget` (folder) deletes this project's records (plain deletion of its store folder); `forget --all` deletes every project's records but keeps the key file, `FORMAT` and `bin/` (it removes `faults.log`), confirm word `all`; `forget --before` drops older points and frees blobs now (no grace, no quiet check; leaves faults and restore records). `retain` accepts 1..=3650 days per project. The `log` footer is printed only when there are turn rows.

## 8. Destructive commands (src/destructive.rs, hook.rs PreToolUse)

`judge(cmd, dirs) -> Verdict {Clear, Save, Remote(rule), UserOnly, Store}` is a pure text reader (also `judge_with`, `store_needles`, `script_dirs`). `Save`: a visible `pre_bash` point (note = masked preview) before the command runs. `Remote`: `ask` in default/acceptEdits/plan, otherwise `deny`, with a save point on `ask` only. `UserOnly` (the model running `torpor off|on|forget|retain`) and `Store` (commands naming Torpor's store or key file) are denied. Never an `allow`. Texts: "Torpor: this command can delete data outside this computer ({rule}). Save points cannot bring that back. Approve only if you meant it." and for sessions that skip prompts "Torpor stopped this because this session skips permission prompts ...".
Order in `hook::handle`: the Store and UserOnly denies are returned before the store is opened and before the off switch is read, so they hold with a broken or missing store and while Torpor is off. The Remote answer is kept as a fallback (`Shared.fallback`) and emitted if the event fails or times out; in the normal path it comes from `pre_tool`, which does not run while Torpor is off (off = no save points and no questions).
Reader limits (the README repeats them for users): aliases, shell functions, `eval`, scripts called by name, `$(...)` inside double quotes, `git rm`/`git mv` as triggers, `cat <<EOF | psql`. Commands over 1 MiB are cut and count as at least `Save`. Heredoc bodies are ignored unless the command is a shell or an SQL client. SQL words are not scanned for text-only tools. Spec-literal false positives remain: `sed 's/truncate/x/'` or `cargo test truncate` can be denied in a no-prompt session; `command -v rm` gets a spare save point. Multi-word remote rules match in order, not adjacent. `cd` into the store marks later writers.

## 9. Deviations from the spec (reason in brackets)

S1a (all still valid):
1. Databases are raw-copied, never opened or backed up with the SQLite API (P10: opening a WAL db writes next to it, which violates A6).
2. P2 continuation rule: a `<task-notification>` prompt with the same `prompt_id` reopens the turn (spec 4.1 had no such case).
3. "Shared before shell" ordering: during an overlap the main agent's own shell edits are listed as `shared` (attribution cannot be split in slow mode).
4. A path that is transiently `x:` in one scan and normal in the next is classed `outside` (no better evidence).
5. `meta.consumed_event_id` watermark and ns timestamps (the spec leaves both open). Tool points invisible. Carry-forward rule for paths the budget did not reach. The timing scan (walk + stat, parallel when the file count is unknown, re-scan once if > 40 ms) chooses slow or fast mode.
6. Low disk: a turn row with NULL `start_point`; the next UserPromptSubmit writes End + Start points.
7. The transcript reader skips ahead to the last 4 MiB. The Stop line's "N files not saved" counts only NEW `x` entries and counts per path net (including mode changes).
8. `Ws::open_in(home, root, create)` added (the spec has only `open`). Marketplace `source "./"` is accepted by `claude plugin validate`; the real install resolution is NOT VERIFIED.
9. The scan thread overlaps `load_cache`; the WAL is kept between hooks with `Ws::drop` truncation (needed for the p50 budget).
10. The harness's `check_contract` accepts a PreToolUse `permissionDecision` of `deny` or `ask` only (never `allow`; the reason must start with "Torpor"). **S2 must relax it** for PostToolUse `additionalContext` and the Stop `decision`.

S1b:
11. Modes as in section 6 (lead's decision). `torpor on` is user-only too.
12. No `pre_bash` point on a command that is denied (remote, store, user-only); the point is made on `ask`. A missing or unknown `permission_mode`, and `auto`, `dontAsk`, `bypassPermissions`, get `deny`.
13. The protections for Torpor's own files and the user-only commands stay active while Torpor is off; the Remote ask/deny does not.
14. The edit-family PostToolUse makes no point. Empty folders are not recreated or removed by undo unless derived from file entries. A secret text-merge is a conflict.
15. If the commit of an event fails after an `ask` was decided, the ask is lost (accepted, fail-open).
16. `CLAUDE_CODE_MANAGED_SETTINGS_PATH` is honored (tests use it for isolation); the OS managed-settings folders were derived from binary strings (NOT VERIFIED); `strictPluginOnlyCustomization` is only a hedged note (NOT VERIFIED).
17. The `.torporignore` precious opt-out reads only the top-level file (about 20 lines, one unit test).
18. `forget --all`, `forget --before`, `retain`, the `log` footer and the user-only guard behave as in section 7; the guard treats any non-empty `CLAUDECODE` as set.
19. The shipped binary must come from a plain build with no features in its own target dir (`CARGO_TARGET_DIR=target/dist`), checked by `tests/release_ignores_fault_env.sh <binary>` (whole seconds, so it also runs on macOS) in CI and in the release workflow.
20. Windows is excluded from `release.yml` (the code uses `std::os::unix` and does not compile there) and kept as an experimental `continue-on-error` CI job.
21. A10 runs `undo 1` in place after `back 1` (section 2). MSRV 1.89 is declared in `Cargo.toml` but NOT VERIFIED (rustc 1.97 was used).
